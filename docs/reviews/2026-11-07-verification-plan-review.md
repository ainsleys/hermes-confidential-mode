# Adversarial review of docs/WORKSTREAM-independent-verification.md (2026-11-07)

Fresh reviewer, SDK source (tinfoil 0.14.2, ehbp, sigstore-python 4.5.1) read, nothing run. [unverified] marks points not confirmable offline.

## Ranked findings
1. CRITICAL. V2 cannot be built as written: GitHub's attestations API is keyed by the artifact (subject) digest, not by the measurement; the digest comes from release metadata. Selecting a bundle by measurement would accept any historically signed build (a downgrade path) or cause re-approval churn. Take the digest from releases/latest, never select by measurement.
2. HIGH. V2 overclaims: the repo is the vendor's; policy is issuer+repo+tag ref; releases/latest is unsigned. V2 removes only the vendor PROXY as a trust point. Use at pin staging/approval as a display cross-check, not at every TTL refresh. "Latest at the time" stays RECORD ONLY.
3. HIGH. Online Rekor lookup adds no cryptographic assurance: verify_dsse already checks the signed entry timestamp, Merkle inclusion proof, signed checkpoint and entry/body consistency offline. Drop the online lookup; extract logIndex and integratedTime from the stored bundle and print them with a search link. [unverified] Rekor v2 may drop the v1 lookup API.
4. HIGH. V1 "independent" means less than it sounds: the expected measurement M is vendor CI's; TCB/policy constants copied from the SDK make it a second vendor policy; ARK/ASK fetched from KDS is TOFU over WebPKI and needs network (contradicting "stored evidence only"; replay's network ban only patches requests/urllib); sends stay gated by the SDK alone; same process, so a malicious SDK can patch the checker and controls EHBP anyway; shared crypto libraries; TDX firmware acceptance is vendor-signed. Honest independence = "AMD hardware signed a report containing M, T, H under a VCEK chaining to a pinned AMD root". Pin ARK/ASK SHA-256 in plugin source; checker in a standalone module with no tinfoil import.
5. HIGH. V1 re-implementation traps: self-consistent fixtures hide shared misreadings (no real capture exists; a real capture is a blocking prerequisite); r||s little-endian at 0x2A0 to DER; signed region 0x000-0x29F; fail-open bugs: TCB compared as one integer instead of per component, Genoa vs Turin TCB layout, checking only reported_tcb (hypervisor-settable; SDK checks current/committed equality), omitting debug/migrate_ma policy bits, omitting VCEK TCB-extension equality. SDK checks neither VMPL nor AMD CRLs; an honest checker should, so it will disagree on purpose: define per-column verdicts.
6. HIGH. V1 TDX not doable by 11-11 (collateral_tdx.py 2125 lines; collateral via vendor proxy can be stale-but-unexpired); router discovery is random across SEV/TDX so "ok requires both" breaks half the rows. Independent column = n/a for TDX; recommend configuring an SEV router host.
7. HIGH. Receipt wording "verified by: vendor SDK + independent check" would be false for the live decision; say "evidence replays under: vendor SDK 0.14.2 [pass]; plugin SEV checker sha256:<file hash> [pass|n/a]; sends were gated by the vendor SDK only". Identify the checker by file hash; PLUGIN_COMMIT is "unpackaged" in source checkouts.
8. HIGH. V4 proves validity plus a name match: cli_replay takes expected fingerprints from the receipt's own rows; take them from pins.yaml or a flag. Repo names can be renamed/transferred; bind the Fulcio cert's numeric Source Repository ID and Owner ID (OIDs 1.3.6.1.4.1.57264.1.15/1.17). Host and captured_at are capturer-asserted; label them. Acceptance list has no V4 tests.
9. HIGH. V3 key regression ill-defined: the SDK's silent re-attestation path never reaches the ledger (existing bug: guard compares fingerprints only, discards capture, writes no verify_ok, so sends map to an earlier verify row with a different H); replicas may alternate keys; max_key_age is a lower bound from first-seen and would refuse a healthy long-lived enclave. Fix the silent re-attest gap first; key first-seen is warn-only. TLS fingerprint T is never used on the EHBP path.
10. MEDIUM. Per-request enc/nonce hashes have no evidentiary value (any X25519 point is valid for any key) and create linkability against the operator's logs. Drop. Record instead the HPKE key the transport was built with (vs the report's H) and that the response AEAD-decrypted (responder held H's private key).
11. MEDIUM. Transport description wrong for this plugin: the enclave-URL header is injected only when base_url differs from the enclave; the plugin talks to https://{enclave}/v1 directly. Where TLS terminates is not established. Cheapest real identity gain: capture the peer certificate on the EHBP connection and check SPKI SHA-256 == T and the SDK's SAN binding; fills tls_cert_binding and gives a CT timeline. Either outcome belongs in the receipt.
12. MEDIUM. GitHub API limits: 60/hour unauthenticated; 300 s TTL plus per-loop pools exceed it. Bundles are immutable per digest (cache forever); only releases/latest refreshes. Fail-closed = outage refuses sends; fail-open = V2 adds nothing at runtime. [unverified] multiple attestations per digest; select by predicateType.
13. LOW. Restated policy must be at least as strict as the SDK's: re.escape(tag) and \Z; reject legacy bundles, unknown in-toto fields, duplicate SCTs; exactly one subject and expected predicateType; add OIDC issuer V2, numeric repo/owner IDs; record and pin Build Signer URI (OID 1.9) and source commit digest (OID 1.13).
14. LOW. Citations: TDX key split is attestation_tdx.py:230-237.

## Verified as correct
Sigstore policy shape and measurement comparison; "latest" from the vendor proxy and bundle from the same proxy; report_data = 32-byte TLS SPKI fingerprint || 32-byte HPKE key; response keys = HKDF(enc || nonce), AES-256-GCM, silent re-attest on mismatch; sigstore-python is vendor-independent; public-good TUF root is the right independent trust root; the four vendor asks are correctly scoped, with the addition that the AEAD gives the client implicit, non-transferable response authentication worth recording.
